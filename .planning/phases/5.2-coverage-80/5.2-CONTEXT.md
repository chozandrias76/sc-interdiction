# Phase 5.2: Coverage to 80% - Context

**Gathered:** 2026-01-22
**Status:** Ready for planning

<vision>
## How This Should Work

Strategic targeting of the highest-impact coverage gaps. Rather than grinding through every file systematically, focus on the files with the most uncovered lines first to get the biggest wins toward the 80% threshold.

The test approach should follow the code structure — snapshots for rendering logic (like views), unit tests for pure logic (like handlers and data processing). Let the code itself guide what kind of test makes sense.

</vision>

<essential>
## What Must Be Nailed

- **Meaningful coverage** - Tests that actually catch regressions, not just lines covered for metrics. Every test should have a purpose beyond bumping numbers.
- **Strategic prioritization** - Focus on high-impact files first (map.rs at 164 lines is the biggest opportunity)

</essential>

<boundaries>
## What's Out of Scope

- No specific exclusions — 100% coverage and refactoring for testability are both acceptable if they serve the goal
- The constraint is organic: stop when we hit 80% with meaningful tests

</boundaries>

<specifics>
## Specific Ideas

- Use snapshots for rendering code (views)
- Use unit tests for logic code (handlers, data)
- Priority order roughly: map.rs (164) → keys.rs (65) → hotspots.rs (30) → smaller files

</specifics>
